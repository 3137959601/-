# 嵌入式软件秋招学习库

> 目标：把知识学习、面试题、手写代码、Debug、性能优化、项目追问和错题复盘统一到一个可持续更新的 GitHub 仓库中。

## 1. 使用方式

本仓库采用六层结构：

1. **知识库**：按 C/C++、Linux、FreeRTOS、计算机网络、FPGA、算法、项目问答分类。
2. **错题本**：记录真正暴露出的认知漏洞，而不是机械抄题。
3. **真实企业题库**：只收录有来源的企业笔试/面试题。
4. **训练题库**：根据真实面经和知识薄弱点派生的训练题，必须明确标记“训练题”，不得冒充企业真题。
5. **答案与解析库**：题目正文与答案分离，通过相对链接跳转。
6. **来源索引**：统一记录公司、时间、岗位、轮次、来源 URL 和可信度。

## 3. 学习状态标记

- 🔴 **未掌握**：核心结论错误，或无法完成基础题。
- 🟡 **理解但不稳定**：能回答主干，但追问、代码或工程场景容易卡住。
- 🟢 **已掌握**：连续复测正确，能够解释原理并完成基础代码。
- 🔵 **面试级掌握**：能够应对连续追问、手写代码、Debug 和工程权衡。

重要度：

- 🔥🔥🔥：秋招高频，必须掌握
- 🔥🔥：常见，应掌握
- 🔥：项目/岗位相关
- ○：了解即可

## 4. 题型编号

统一使用以下题型前缀：

- `K`：Knowledge，知识问答
- `C`：Coding，手写代码
- `D`：Debug，现场找 Bug / 修 Bug
- `O`：Optimization，性能、内存、实时性或资源优化
- `E`：Engineering，工程场景题
- `CTRL`：控制/状态机/嵌入式逻辑题
- `P`：Project，项目追问
- `ALG`：Algorithm，算法与数据结构

示例：`LINUX-C-001`、`FREERTOS-D-003`、`CPP-O-002`。

## 5. 真题与训练题必须分离

### 真实企业题
必须至少记录：
- 公司
- 时间
- 岗位（未知则写“未注明”）
- 面试/笔试轮次（未知则写“未注明”）
- 原始来源 URL
- 题目原意
- 来源可信度

### 训练题
必须标记：
> 类型：AI/导师派生训练题，不是企业原题

训练题可以根据：
- 最近 12 个月公开面经的高频题型
- 当前错题
- 简历项目
- 目标岗位 JD
派生，但不得伪造企业出处。

## 6. 答案跳转规范

题目后统一提供答案链接，例如：

`[查看答案与解析](../答案/Linux答案.md#linux-c-001-手写环形缓冲区)`

答案标题中的题号必须与题库完全一致，确保 GitHub Anchor 可跳转。

## 7. 每个知识点的练习规则

不是每个知识点都机械加题。满足以下任一条件时必须添加练习：

- 🔥🔥🔥 高频知识
- 容易和其他概念混淆
- 能自然考手写代码
- 能设计 Debug 题
- 能设计工程场景
- 与目标岗位或简历项目强相关
- 用户当前状态为 🔴 / 🟡

推荐每个重要知识点：
- 1 道口述题
- 1 道追问题
- 1 道代码/Debug/工程题（适合时）

## 8. 学习闭环

学习一个知识点后按以下流程更新：

知识讲解  
→ 用户口述  
→ 面试追问  
→ 必要时手写代码  
→ Debug / 优化  
→ 判定掌握等级  
→ 更新知识库  
→ 错误进入错题本  
→ 新题进入题库  
→ 答案进入解析库  
→ 安排复测

## 9. GitHub 同步检查点

**固定规则：每次完成一个有实质学习内容的阶段，导师应主动检查是否产生以下内容：**

- 新知识总结
- 新错题/薄弱点
- 掌握状态变化
- 新企业真题
- 新训练题
- 新答案/解析
- 项目问答更新

只要存在任意一项，就在对话结束前提醒：

> “本轮有可沉淀内容，建议同步 GitHub。”

如果当前 GitHub 连接具备写权限，则在用户明确授权提交后执行写入；若用户已在当前指令中明确要求本轮更新，则无需重复询问同一授权。

> 注意：不能依赖聊天长期记忆保存该规则。每次重新开展系统学习时，应优先读取本 README 恢复规则。

## 10. 来源可信度

- `A`：公司官方题库、官方招聘流程、官方技术资料
- `B`：候选人公开面经，包含明确公司/时间/岗位
- `C`：二次整理帖、经验汇总
- `D`：无法验证出处，仅作为训练灵感，不登记为企业真题

## 11. 维护原则

- 不追求“题越多越好”，优先收录高频、可迁移、能暴露能力差距的题。
- 不把答案写成背诵长文，答案应包含“30~90 秒面试版 + 原理版 + 追问 + 代码/陷阱（如适用）”。
- 错题要记录“错误模式”，而不仅是某一道题。
- 同一题在多家公司出现时，不重复复制答案；在来源索引中增加来源记录即可。
