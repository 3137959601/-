## E-K-002

**为什么 ADC 采样常配合 DMA？**

[返回例题](../嵌入式秋招八股文_项目问答.md#q-e-k-002)

DMA 可以在外设与内存之间搬运数据，减少 CPU 对每个采样点逐次读寄存器的参与。高采样率场景下，它能降低 CPU 占用和中断频率；常结合循环 DMA、半传输/全传输中断和双缓冲，形成连续采集流水线。

定时器确定采样时刻，DMA写A时任务处理已完成的B；收到完成事件后交换所有权。任务不得读取DMA正在覆盖的区域，有D-cache时执行平台要求的同步。若持续处理不过来，需背压/降采样/丢整块并计数；加缓存只能缓冲短突发。

## CTRL-D-002

**修复阻塞式控制循环**

[返回例题](../嵌入式秋招八股文_项目问答.md#q-ctrl-d-002)

### 常见坏味道
- 主循环大量 `delay`
- 一个状态等待传感器时阻塞整个系统
- while 等待标志位且无超时
- ISR 内执行长耗时逻辑

### 优化
拆成显式状态机 + 时间戳 + 事件驱动；所有等待都设置超时；ISR 只做最小工作并通知任务。

具体可拆WAIT_SENSOR→PROCESS→WAIT_NEXT；WAIT_SENSOR每轮仅检查ready与截止时间，到期进ERROR/RETRY，WAIT_NEXT用时间戳判断而非阻塞delay。每轮都服务UART接收；重试有次数/总时限上限，错误后清理在途资源再重新启动，日志移至低优先级任务。

## E-C-001

**寄存器位操作**

[返回例题](../嵌入式秋招八股文_项目问答.md#q-e-c-001)

假设 `reg` 为一个 32 位寄存器变量：

```c
reg |=  (1u << n);   // 置 1
reg &= ~(1u << n);   // 清 0
reg ^=  (1u << n);   // 翻转
```

### 面试追问
- 为什么常写 `1u`？
- 如果 `n >= 32` 会怎样？
- 对真实 MMIO 寄存器为什么要看芯片手册的读写属性？

读取：bit=(reg>>n)&1u。要求掩码类型至少32位、n<32，可用UINT32_C(1)明确类型。W1C、读清零等位按手册访问，不能套用普通读改写。

## CTRL-C-001

**非阻塞按键消抖状态机**

[返回例题](../嵌入式秋招八股文_项目问答.md#q-ctrl-c-001)

```c
typedef enum {
    KEY_IDLE,
    KEY_DEBOUNCE_PRESS,
    KEY_PRESSED,
    KEY_DEBOUNCE_RELEASE
} KeyState;

typedef struct {
    KeyState state;
    uint32_t t0_ms;
} KeyDebounce;

bool key_update(KeyDebounce *k, bool raw_pressed, uint32_t now_ms) {
    const uint32_t debounce_ms = 20;

    switch (k->state) {
    case KEY_IDLE:
        if (raw_pressed) {
            k->state = KEY_DEBOUNCE_PRESS;
            k->t0_ms = now_ms;
        }
        break;

    case KEY_DEBOUNCE_PRESS:
        if (!raw_pressed) {
            k->state = KEY_IDLE;
        } else if ((uint32_t)(now_ms - k->t0_ms) >= debounce_ms) {
            k->state = KEY_PRESSED;
            return true; // 仅在确认按下时产生一次事件
        }
        break;

    case KEY_PRESSED:
        if (!raw_pressed) {
            k->state = KEY_DEBOUNCE_RELEASE;
            k->t0_ms = now_ms;
        }
        break;

    case KEY_DEBOUNCE_RELEASE:
        if (raw_pressed) {
            k->state = KEY_PRESSED;
        } else if ((uint32_t)(now_ms - k->t0_ms) >= debounce_ms) {
            k->state = KEY_IDLE;
        }
        break;
    }
    return false;
}
```

### 为什么比 `delay_ms(20)` 好？
它不会阻塞主循环或任务，可以同时处理通信、控制和其他外设。

需包含 <stdbool.h>、<stdint.h>；初始化KeyDebounce k={KEY_IDLE,0};，调用前保证k有效。无符号差允许计时回绕，但两次相关观察不能跨越完整计数周期，也不能把极长未检查区间误当短间隔。状态机只确认一次按下，稳定释放后才能再次触发。
